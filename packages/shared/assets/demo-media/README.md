# Demo media (DEMO, synthetic)

Generated by `packages/shared/scripts/gen-demo-media.ts` (blueprint step 92, D50/D51). Do not edit by hand;
regenerate instead. Everything here is synthetic demo material for the DEMS demo stack.

## Regenerate

```sh
cd packages/shared
node --import tsx scripts/gen-demo-media.ts --as-of 2026-10-01T10:00
```

- `--as-of` is the simulator time the media is dated for, in WIB (a date alone means 10:00 WIB). The
  previous-day sessions depend only on its date; today's follow-up sessions are placed before it (step 32), so
  their burned-in OSD times match the simulator only when the demo loads near that time. The audio does not
  depend on it.
- Requires the Homebrew formulae `ffmpeg` and `espeak-ng` (host install and rollback: step 92 log,
  docs/2026-09-30_dems_demo_stack_setup/implementation/64_demo_media.md).
- The run is deterministic: the same `--as-of` and tool versions give the same files and SHA-256 values
  (listed in `media-index.json`). Regenerate step 93's evidence packages after regenerating media.

- Per evidence item (`evidence/<evidence number>/`, the join key): `VIDEO-01.mp4` (Camera 1, wide) and `VIDEO-02.mp4` (Camera 2, mirrored reverse-angle crop),
  H.264 1280x720 at 25 fps, no audio stream; `AUDIO-01.m4a` (MIC 1, interviewer) and
  `AUDIO-02.m4a` (MIC 2, subject), AAC mono 48000 Hz 48 kbps, two separate files (never mixed, design book §6.3).
  Each is an excerpt from the recording start; its length follows the interview script, not the full session
  duration. Posters (1280x720) and thumbnails (320x180) are the frame at 1 s.
- Excerpt rule (`media-index.json` `excerptRule`): Media cover [0, excerpt.durationMs) of each recording (the full length is sessionDurationMs). A player that shows the full timeline maps position p to p mod excerpt.durationMs and labels playback as a DEMO excerpt. The four tracks of an item always share one duration, so VIDEO-01, VIDEO-02, AUDIO-01 and AUDIO-02 stay in sync under that rule. Live loops (live.excerpt.loop = true) repeat seamlessly. Join media to the simulator by evidenceSuffix (the numeric suffix of EV-YYYYMMDD-NNNN); the live loop by live.sessionSeq, which equals RECORDING_SCENARIO.sessionSeq, and by live.evidenceSuffixWhenSealed once the scenario session is sealed.
- `live/`: seamless loops for the recording scenario session (`RECORDING_SCENARIO.sessionSeq` = 24, Ahmad Fauzi); their OSD has no running clock and no
  REC because the UI overlays both from the simulator clock, and idle camera tiles reuse the loops.
- `mobile/`: 640x360 subset (loops, per-session tracks, posters; audio AAC mono 24000 Hz 32 kbps) with
  flat, lowercase, Android-safe names.

## Note on real capture and version-2 packages (added by hand on 2026-10-10, task 3 row 96, register DOC-04)

This section is NOT written by `gen-demo-media.ts`: a regeneration replaces this file and removes it, until the generator's README text carries it. Everything above is unchanged and still describes this folder exactly.

- The media here are the demo pictures and voices of Simulated mode and of the version-1 demo evidence packages (`../demo-evidence/`): four separate track files per item (`VIDEO-01`, `VIDEO-02`, `AUDIO-01` = MIC 1, `AUDIO-02` = MIC 2). The real-capture task did not change them.
- **A real recording does not use this layout.** The capture worker writes one file per camera with the ONE session audio track (`AUDIO-01`) inside it; `AUDIO-02` exists in the version-1 demo data only. The two microphone inputs are `MIC-01` and `MIC-02` (primary and standby), and which one feeds the session audio at a given time is recorded as intervals.
- **None of these files is used by a version-2 demo package.** The two version-2 demo packages of a development-capture Core are recorded at seed time from generated test sources (a test picture and generated audio) by the Core's helper program, and are sealed into that Core's media store. They are never stored in this folder or in git.
- In Live mode the camera picture shown by the clients is still the demo loop of `live/`; there is no live preview of a real camera in this phase.
- More: the repository `README.md`, section "Real capture, sealing and transcript".
