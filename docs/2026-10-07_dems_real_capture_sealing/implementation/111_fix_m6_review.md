## 2. Raw audio taps are plaintext on disk (statement asked for)

The PCM tap `<dataDir>/transcriber/sessions/<id>/tap.pcm` and the chunk files under `work/` are **unencrypted session audio on disk while the session records and until its seal completes** (mode 0600 in a 0700 folder). This is the same class of limitation as the plaintext camera recordings before the seal (D147). This pass does not encrypt them; it ends their life: they are removed when the package is stored, on a failed start, at a start of the Core for sealed sessions, and by a reset.

## 5. Decisions for the controller

1. **Shared data directory, colliding session IDs (new finding, not in the review).** The transcriber scratch is keyed by `<dataDir>/transcriber/sessions/<sessionId>` and the lanes share `.data` (`scripts/lane/lane.sh` sets only `DEMS_MEDIA_DIR` per database). Two databases in a real capture mode on one data directory share a tap path for equal session IDs, and since this pass a reset of one database removes the scratch of ITS session IDs - which may be the live folder of another database's session of the same ID. The reset removes only the IDs of the database being reset that took a snapshot (never "every folder"), but the collision is real. Proposal: key the scratch by the media store (below `mediaStoreDir`, or `<dataDir>/transcriber/<database>/sessions`).
2. **R80-06, second half.** The marker closes the window in which the frame HAD arrived. A Core that dies before the first telemetry frame of a restarted worker still reopens with "never lost". The full rule (tap length against the session's audio end - the closed row of `session_audio_intervals`) needs a ruling on the tolerance and one real capture to hold the two clocks against each other (media-time origin, late audio start); a wrong assumption would make every transcript PARTIAL. Not built on a guess.
3. **Summary after a start = one manifest read per REAL item** (bounded 64 MB, hashed, schema-parsed). Fine for the demo; a column needs a migration if the store grows.
4. **The summary note reuses the fact door `noteTranscriptRevision`** (no new door in `engine/host.ts`, which other passes edit). If a door of its own is wanted, it is one block.
5. **R80-05, R80-08, R80-10** need a ruling or a refactor row (table above).
6. **Failed start before `begin`**: request to the capture-session owner (section 3).
7. `SessionCompositionDeps.intervals` is REQUIRED now: one member was added to a deps literal in `src/sealing/__tests__/stt-states.test.ts` (M7's test file).
8. The rig of `transcript-routes.db.test.ts` sealed an item with a made-up manifest digest; it now seals with the digest of the package it builds (a real seal's relation), because the boot step accepts no other manifest.
