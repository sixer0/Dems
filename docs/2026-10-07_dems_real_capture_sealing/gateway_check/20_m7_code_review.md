## 3. What was checked and found sound

- GCM construction: AES-256-GCM, 96-bit random nonce, 16-byte tag, AAD `(trackId, seq, byteOffset, keyId)` length-prefixed and big endian; a record of another key ID is refused before decryption (`fragment-cipher.ts:106-119, 141-157, 171-189`).
- Session key: 32 random bytes (`key-store.ts:123`), one file 0600 in 0700 folders under `<dataDir>/credential-store/keys/`, never in the manifest, the journal, a log line or an error (errors carry a code and a position only: `fragment-opener.ts`, `session-key.ts`).
- The sealed file is written under a name of its own, exclusively, synced, then renamed (`camera-files.ts:63-66, 80-83`; `pipeline.ts:341, 404-408`); no link is followed on any read (`O_NOFOLLOW`).
- FINALIZE_HASHES decrypts every sealed range and holds it against the recording-time row and the fragment record before anything is signed (`pipeline.ts:496-507, 514-516`).
- The plaintext removal rule: only a file the signed manifest names, a regular file directly in the folder, with the sealed counterpart present, whose bytes hash to `sha256Plain` (`pipeline.ts:769-826`).
- `FRAGMENT_TOO_LARGE` is refused before a sealed byte or a signature exists, with the verifier's own constant (`pipeline.ts:146, 333-338`).
- Verify never reads a file through a link or outside the folder (`package-reader.ts:40-52`); op 41 requires the plaintext check (`evidence-verify/index.ts:328`) and anchors the manifest digest, the transcript hash and the revision count to the database (`:329-336`).
- `sources.development` is recomputed and is `null`, never `false`, for an untrusted manifest (`verify.ts:877-885`); both clients show DECLARED_PRODUCTION only for `code === 'DECLARED_PRODUCTION' && development === false` (`verify-v2.ts:290` web, `:295` mobile).
- V-11 binds a revision to its body, to the item and to the transcript hash of the SIGNED manifest (`verify.ts:673-722`).
- One signing key location for the boot check and the seal (`signing.ts:26`, `boot/checks.ts:49`, `boot/index.ts:157`); a key file readable by others is refused (`signer/host-key.ts:68`).
- Reset: package removal holds the containment rule (name form, not a link, a direct child of the resolved root: `package-removal.ts:55-80`) and judges each folder a second time at removal (`real-evidence.ts:440-463`); a conflict between `DEMS_MEDIA_DIR` and the recorded root refuses (`cli.ts:146-168`).
- Demo seeding: development key or nothing, never over an existing folder, both items or none (`seed-hook.ts:128-144`; `demo-packages.ts:150-163`).
