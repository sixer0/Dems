## 3. `apps/mobile/scripts/device-session.sh` (P3, 05 §5.4 finalised)

```
METRO_PORT=<lane> apps/mobile/scripts/device-session.sh phone|tablet|both '<commands>'
NO_METRO=1 … (installs, launcher checks)     KEEP_APP=1 (no force-stop)     LOCK_WAIT / SESSION_MAX_SECS / BOOT_WAIT
```

What it does:
1. **Locks.** It takes `.locks/dems_<avd>.lock` with `/usr/bin/lockf -k -t ${LOCK_WAIT:-1800}`. For `both` it takes the phone lock first, then the tablet lock, and re-runs itself inside the lock(s).
2. **AVD check.** The emulator *process* (`pgrep -f`) decides whether the AVD is running; adb is not asked first (F-2).
   - If the AVD is down, the helper boots it the P3 way: `-port 5554/5556 -no-metrics -gpu host -no-boot-anim -no-snapshot-save`. The emulator is detached (setsid, fds above 2 closed), its PID goes to `.locks/dems_<avd>.pid`, and the helper waits for `sys.boot_completed`.
   - It never boots a second copy of a running AVD.
3. **Force-stop.** It force-stops `com.dems.demo.tablet` (D43), unless `KEEP_APP=1`.
4. **Metro.** It starts Metro on `127.0.0.1:$METRO_PORT` (ipv4first, D41) and waits for `packager-status:running`.
   - It refuses to start if the port already answers (exit 70).
   - It sets the app's bundler location to `localhost:8081` (F-1).
   - It sets `adb reverse tcp:8081 tcp:$METRO_PORT` and `tcp:4400 tcp:4400`.
5. **Commands.** It runs `<commands>` in `apps/mobile`, in their own process group, with these exported: `SERIAL`, `ANDROID_SERIAL`, `SERIALS`, `APP_ID`, `METRO_PORT`, `METRO_LOG`, `ROOT`, `APP` and `SHOTS`, plus adb and the emulator on `PATH`.
   - After `SESSION_MAX_SECS` (1800 s) the whole group is stopped (exit 142).
6. **Cleanup.** On any exit it stops Metro, force-stops the app and removes only this session's reverse rules. **It never stops an emulator.**

Exit codes: the status of `<commands>`, or 64 (usage), 69 (device unavailable), 70 (Metro failed or port busy), 75 (lock timeout) or 142 (session cap).

### F-1: stock emulators bypass `adb reverse` by default

Before the setting (Metro on 8083, reverse `tcp:8081 tcp:8083` set, host 8081 free), the app never reached the lane Metro. It showed a red "Unable to load script" screen: [67_dems_phone_hmb09_default_host.png](assets/mobile/67_dems_phone_hmb09_default_host.png). Logcat:

```
W unknown:ReconnectingWebSocket: Couldn't connect to "ws://10.0.2.2:8081/message?device=sdk_gphone64_arm64…"
W unknown:ReactNative: The packager does not seem to be running … Failed to connect to /10.0.2.2:8081
E unknown:ReactNative: java.lang.RuntimeException: Unable to load script.
== Metro requests: 0
```

- **Cause.** The build fingerprint is `google/sdk_gphone64_arm64/…`. React Native treats this as a stock emulator and uses `10.0.2.2:8081`, which is the **host** loopback, instead of `localhost:8081`. So the device-side reverse rule is never used.
- **What this means for earlier steps.**
  - Rows 18 and 19 worked only because Metro was on host 8081.
  - Without a setting, every lane would reach whatever runs on host 8081, and lanes on 8082–8086 would fail.
- **Fix.**
  - `device-session.sh` writes React Native's own bundler location, `debug_http_host=localhost:8081`, into `shared_prefs/com.dems.demo.tablet_preferences.xml` through `run-as`. This is the Dev Menu's "Change Bundle Location" setting.
  - `run-as` works because the debug build is debuggable.
  - The helper keeps any other entries in that file.
  - It runs on every session start, after the force-stop, so the next app start picks it up.
- The setting survives `adb install -r` and emulator restarts. A data wipe clears it, and the next session writes it again.
