## 0. Common root threat (S13-11 as a whole), SEC:231
"The scan, the set-IP job and the typed probe make the Core open connections to addresses a signed-in person supplies ... Without rules this is a request-forgery reach: a technician account, or whoever holds one, uses the Core to touch hosts on the office network or the Core itself, and, with set-IP, sends a digest there." input-av bounded only the stored list to private IPv4 (`IAV/nvr/settings.py:69-78`) and left the ONVIF port free (`IAV/nvr/factory.py:154`). Requirement: one pure function decides before any packet leaves (SEC:233); check = table test plus "0 packets sent" (SEC:240).
The threat is split per point below; note only point 2 names the office network specifically as the target of the SEC:231 risk, but point 1 also covers "the Core itself".

## 2. Which threat belongs to point 2 versus the rest (for row 89)
- **Only point 2 (and DR-4, S13-08 pt 3, SN-5, R-23) answers "Core acts on / routes via the wrong network"**: wrong-source-interface and office-LAN reach (SEC:235 vs SEC:231; SPEC:397,419,460,583). This is what D10(2)/D11 cancel (decisions.md D10 line 23, D11 line 24: "Core bisa dial ke perangkat lain di jaringan kantor").
- **Points 1, 3, 4 are independent of which interface is used**: forgery to loopback/Core/special/public addresses and names (1), arbitrary ports/redirects/replies (3), flooding/scan size (4). Lifting pt 2 does not weaken them, but pt 1's host-own refusal and pt 2's source binding interact: RULE:355-366 chooses `sourceAddress` from the camera interface, so a global rule needs a new source-selection statement (not a threat question; design for row 89, not decided here).
- **AD-02 is a stored-data-integrity threat**, not a network-location one. It uses pt 1 (not pt 2) at every use of a stored address. It stays valid under "Global penuh" provided the pt 1 refusals stay. (Inference from ADD:157-160; hypothesis for row 89.)
- **S13-08 pt 2 (alias /24, RFC1918, host 1-254)** protects the privileged helper from being a re-addressing tool; it is independent of pt 2 of S13-11 and of the camera-interface restriction of reading/dialling. If scan/set-IP stay on the configured interface (RQ-N2), the helper and its pt 3/DR-4 copy are unchanged.
- Residual pt 2 element not found in the 2026-10-12 plan as a separate rationale: why the connection is bound to a "camera-interface address" beyond B-7/H-U (e.g. return-path / ufw HOST-19..23 isolation is cited only in D11). HOST-19..23 text: not found in the files I read; cited by decisions.md:24 only.
