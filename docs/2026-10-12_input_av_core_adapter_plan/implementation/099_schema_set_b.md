## 3. Design differences, each a driver decision (section 9)

1. **Addresses are `text` with a CHECK, not `cidr` / `inet`.** The design names the address types and gives text as the fallback "with no loss of function" (hypothesis H-DB-3). Not tested with the generator: two tests hold the contract's column types to a closed list of nine (`contract-inventory.test.ts:186`, `catalog.db.test.ts:394`, rule TY-1), and the reset carry, the digests and the driver would each meet a new type. Patterns: `camera_subnet` = dotted IPv4, prefix 16..30; `host_network_aliases.address` = `a.b.c.d/24` inside 10/8, 172.16/12 or 192.168/16, host part 1..254 - exactly the helper's request token and bound (S13-08 (2)).
2. **One open alias at all**, beside the design's "one per address". The design allowed several; the helper as delivered holds one. Undo if `MAX_MARKED` is raised: one `DROP INDEX` in a later set.
3. **`factory_addresses` is bounded in the database** (S13-13, "no free JSON"): an array, at most 32 elements, each a text of the dotted form. The design left the elements to the module; whether an address is private stays the module's rule.
4. Four CHECKs beyond the design's column table on T-47, all narrowing: `removed_by` only on a closed row; `remove_reason` set exactly when `removed_at` is; `removed_at >= added_at`; `remove_error` a CODE.
