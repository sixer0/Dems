## Behaviour

| Rule | As built |
|---|---|
| TECHNICIAN only (U10) | Live: the sidebar entry is rendered only while the Core's permission list holds `CAPTURE_COMMISSION`; the route guard sends everybody else to the Dashboard with the shell's "refused page" notice. Simulated (by address; the sidebar hides permission entries there): another role sees the role sentence, no panel, no control, and nothing is requested |
| Nothing scans by itself (U9) | opening the page sends two reads (101, 104); a scan is ONE request on one press, with at most one typed address |
| A write needs production capture operation | said always ("Saving these settings, a scan and removing a temporary address need a Core running in production capture operation. On any other Core they are refused and nothing changes."); once a write is answered `COMMISSIONING_NOT_AVAILABLE` the screen keeps the notice "This Core is not running in production capture operation: ..." |
| A camera outside the list is found only by a typed address | said at the factory list (its hint) and at the scan |
| Settings | interface, subnet, factory list (one per line, at most 32, each once), alias host part, alias lifetime, first camera address; validated in the form by the contract's patterns and bounds (inline per field); the body carries `revision` and only the changed settings; an unchanged form sends nothing; a stale revision reads the row again |
| Alias state | "No temporary address is in place.", or the address `/24`, what it was added for, when, when the host removes it, a failed removal's code, "Remove now" (105) and "Read again" (104); a scan's answer updates it |
| Refusals | the contract's sentence for each of the 13 `CaptureCommissioningReason` (with `details.cause` as "Helper code: X."), and the console's for the lock, a stale revision, the role, a body not accepted, an unanswered request; never the answer's text |
