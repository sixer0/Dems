## Recommendation, in one line

A root service on a local socket, one short-lived helper instance per connection, so that the Core's unit keeps `NoNewPrivileges=yes` and an empty capability set; `sudo -n` only by a later exception row that names the host and the reason and is confirmed by the user (none known for Ubuntu 24.04).

## Why

`sudo` is a set-user-ID program and cannot become root under `NoNewPrivileges` (`systemd.exec(5)`, fetched 2026-10-12); input-av's own unit says it sets neither option for that reason (`apps/input-av/deploy/dems-nvr.service:19-20`). A helper started by the init system on a socket connection is not a child of the Core and is not bound by the Core's option (same manual page). The helper's nine bounds of S13-08 are unchanged in either form.

## Options compared

Six: socket with one instance per connection (chosen); socket daemon; `sudo -n`; set-user-ID or file-capability helper; a unit started through a policy rule; `CAP_NET_ADMIN` on the Core (already ruled out by SN-2).
